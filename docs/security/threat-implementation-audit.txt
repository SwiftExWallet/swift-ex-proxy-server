T23 - Implemented
Redis production TLS/auth/ACL validation exists, rate limiter Redis clients
disable offline queue, and rate limiting now has route-level Redis outage
policies: fallback-memory, fail-closed, and fail-open. The default policy is a
low-threshold memory fallback, while Redis-backed Fusion+ order build/submit/
confirm routes opt into fail-closed behavior. RedisService tracks health state,
provides ping-based health checks, and can enforce configured Redis persistence
with REDIS_PERSISTENCE_REQUIRED plus REDIS_PERSISTENCE_MODE=snapshot, aof, or
managed.
Remaining deployment responsibility: Redis HA, actual durable storage/backups,
and managed-provider persistence settings must still be configured outside the
application.
Evidence:
- src/api/v1/common/config/datastore.config.ts
- src/api/v1/common/guard/rate-limit.guard.ts
- src/api/v1/redis/redis.service.ts
